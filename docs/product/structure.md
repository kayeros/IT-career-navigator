# Структура итоговой платформы «Карьерный навигатор IT»

Версия платформы для акселератора: MVP → пилот → первые 100 пользователей и подписка
**Версия документа:** черновик от 07.10.2026 для обсуждения в команде. **Автор:** Юрий Логинов.

> Сконвертировано из «БД и структура/структура_итоговой_платформы.docx» 21.10.2026. Источник истины — docx; при изменениях обновлять этот файл.

# 1\. Рамки документа

  - **Что это.** Полная структура той версии платформы, которую мы строим и показываем в рамках акселератора: на демо-дне, в заявке на грант ФСИ «Студенческий стартап», при регистрации программы для ЭВМ и на пилоте в УУНиТ.

  - **Чем отличается от прототипа.** Прототип («структура\_платформы.docx») — только экраны и переходы. Здесь — вся логика: данные, расчёты, ИИ, подписка, админка, уведомления, метрики и требования.

  - **Чем отличается от «большой» платформы.** Без масштабирования: нет мобильного приложения, кабинета для вузов, подбора вакансий и откликов, менторов и сообщества. Полный список — в разделе 12.

  - **Как читать.** Разделы 2–6 — что и для кого строим. Раздел 7 — подробно по каждой странице. Разделы 8–11 — логика, админка, аналитика и требования. В конце — этапы и открытые вопросы, которые нужно решить командой.

# 2\. Цели версии и критерии успеха

Каждая функция должна работать на одну из целей акселератора. Если функция не помогает ни одной цели — её нет в этой версии.

# 3\. Состав версии

## 3.1. Профессии

  - **В каталоге 10+ профессий,** из них полностью проработаны 10: есть roadmap, ресурсы, тест оценки и веса навыков по вакансиям.

  - **Остальные — карточки «Скоро».** Кнопка «Сообщить о запуске» сохраняет почту. Это одновременно сбор спроса: по числу заявок выбираем, какие треки делать следующими.

  - Какие 10 профессий — решаем по числу вакансий junior на hh.ru и прочих трудовых биржах (в т.ч. телеграм каналы) и результатам опросов.

# 6\. Сквозные сценарии

### С1. Новый пользователь, не знает профессию

1.  Главная → «Начать»

2.  Регистрация → письмо → подтверждение почты

3.  Онбординг: «Не знаю» → профориентация → топ-3

4.  Выбор профессии → карточка (базовый roadmap)

5.  «Узнать мои пробелы» → оценка навыков → краткий отчёт

6.  «Получить персональный план» → тарифы → оплата

7.  Персональный план → персональный roadmap → первый шаг

### С2. Новый пользователь, профессия выбрана

1.  Главная → регистрация → онбординг (профессия из списка)

2.  Сразу карточка профессии → далее как в С1 с пункта «Узнать мои пробелы»

### С3. Покупка подписки

1.  Кнопка подписки (отчёт, план, верхняя панель) → тарифы

2.  Ввод промокода (необязательно) → оплата у платёжного сервиса → результат оплаты

3.  Профессия и оценка есть → план; нет оценки → оценка; нет профессии → каталог

### С4. Обычный день пользователя

1.  Вход → личный кабинет → «Текущий шаг»

2.  Тема в roadmap → ресурсы → «Изучено»

3.  Прогресс и % соответствия обновляются; следующий шаг становится текущим

### С5. Подписка закончилась и продлена

1.  За 3 дня — письмо-напоминание

2.  День окончания → режим «заморожено»: план и roadmap только для чтения

3.  Продление → всё продолжается с того же места

### С6. Рынок изменился

1.  Ежемесячное обновление весов навыков

2.  В плане баннер «Требования рынка изменились — обновить план?»

3.  Пользователь решает сам; старая версия плана сохраняется

### С7. Вторая профессия

1.  Каталог → другая профессия → оценка → новый план

2.  В личном кабинете переключатель между планами

### С8. Пилот УУНиТ

1.  Команда выдаёт группе промокод на бесплатный период

2.  Студент регистрируется → вводит промокод в профиле или на тарифах → получает подписку

3.  После пилота — опрос и отзыв, данные идут в отчёт по пилоту

### С9. Забыл пароль

1.  Вход → «Забыли пароль?» → почта → письмо со ссылкой → новый пароль → вход

# 7\. Страницы подробно

## 7.1. Общие элементы

**Верхняя панель**

  - Гость: логотип · Каталог · Тарифы · Войти · кнопка «Начать бесплатно»

  - Авторизованный: логотип · Каталог · Мой план (переключатель профессии, если их несколько) · Тарифы · иконка профиля (Личный кабинет, Профиль, Выйти)

  - Плашка состояния подписки: «Подписка заканчивается через N дней» или «Подписка заморожена — продлить»

**Подвал**

  - Контакты, ссылки на правовые страницы, форма «Написать нам», соцсети (VK, Telegram)

**Общие правила**

  - Гость нажал на действие, доступное после входа, → вход → возврат туда, откуда пришёл.

  - Любая ошибка сервера → понятное сообщение и кнопка «Попробовать ещё раз», а не пустая страница.

  - Баннер согласия на cookie (используем Яндекс Метрику).

## 7.2. Публичная часть

### П1. Главная

**Адрес:** / **Доступ:** все

*Объяснить ценность за 10 секунд и привести человека в главный путь.*

**Блоки и элементы**

  - Первый экран: заголовок про главную боль («Узнай, чего тебе не хватает до первой работы в IT»), кнопка «Начать бесплатно».

  - Как это работает: 3–4 шага с иконками.

  - Пример отчёта о разрыве (картинка с реальными данными по одной профессии).

  - Цифры о рынке (из презентации) — почему это важно.

  - Профессии: 4–6 карточек из каталога и ссылка на весь каталог.

  - Тарифы кратко и ссылка на страницу тарифов.

  - Отзывы — только реальные (пилот УУНиТ). До пилота блок скрыт.

  - Частые вопросы.

  - Форма обратной связи: имя, почта, сообщение, согласие на обработку ПД.

  - Контакты команды.

**Действия и переходы**

  - «Начать бесплатно» → гость: регистрация; пользователь: онбординг (если не пройден) или личный кабинет.

  - Карточка профессии → её страница.

**Правила**

  - Форма обратной связи сохраняется в админку и приходит письмом команде.

**События аналитики:** просмотр главной, клик «Начать», отправка формы.

### П2. Каталог профессий

**Адрес:** /professions **Доступ:** все

*Показать все треки и помочь выбрать.*

**Блоки и элементы**

  - Карточки: название, короткое описание, зарплата junior (диапазон), спрос (число вакансий junior за месяц), статус «Доступно» или «Скоро».

  - Отметка «Вам подходит» (после профориентации) и «Мой план» (если есть план).

  - Фильтр: доступные / скоро; поиск по названию.

**Действия и переходы**

  - Доступная профессия → её карточка (подписчик без оценки → сразу оценка навыков).

  - Профессия «Скоро» → «Сообщить о запуске» (почта, для пользователя — в один клик).

**События аналитики:** клик по карточке, заявка «Сообщить о запуске».

### П3. Карточка профессии (roadmap)

**Адрес:** /professions/{профессия} **Доступ:** все; режимы зависят от роли

*Главный рабочий экран обучения — карта тем по образцу roadmap.sh.*

**Блоки и элементы**

  - Шапка: название, кому подходит, зарплата junior, спрос, дата обновления данных о вакансиях.

  - Карта: блоки тем, соединённые линиями в порядке изучения.

  - Боковая панель темы: описание, зачем нужна (связь с навыком и % вакансий), ресурсы (бесплатные отмечены, язык), оценка времени в часах, кнопка «Изучено», ссылка «Сообщить об ошибке».

  - Легенда цветов.

**Состояния**

  - **Базовый:** общая карта; у пользователя — отметки «Изучено».

  - **Персональный (подписчик):** темы помечены «уже знаю», «изучить», «текущий шаг», «не обязательно для junior»; показан прогресс.

  - **Заморожен:** то же, что персональный, но без нажатий; плашка «Продлите подписку, чтобы продолжить».

  - **Профессия «Скоро»:** вместо карты — описание и «Сообщить о запуске».

**Действия и переходы**

  - «Узнать мои пробелы» → оценка навыков.

  - «Мой план» → персональный план.

  - «Изучено» → обновление прогресса (без перезагрузки страницы).

**Правила**

  - Гость видит карту и ресурсы, но «Изучено» просит войти.

  - Отметку «Изучено» можно снять.

**События аналитики:** открытие темы, клик по ресурсу, «Изучено», «Сообщить об ошибке».

### П4. Тарифы

**Адрес:** /pricing **Доступ:** все

*Понятно показать, что даёт подписка.*

**Блоки и элементы**

  - Сравнение «Бесплатно» и «Подписка 250 ₽/мес»: что входит в каждый.

  - Поле промокода.

  - Частые вопросы об оплате и отмене.

  - Ссылка на оферту рядом с кнопкой оплаты.

**Действия и переходы**

  - «Оформить подписку» → гость: вход; пользователь: оплата (Л8).

**События аналитики:** просмотр тарифов, клик «Оформить», ввод промокода.

### П5. Регистрация, вход, подтверждение почты, восстановление пароля

**Адрес:** /register, /login, /verify-email, /reset-password **Доступ:** гость

*Простой и безопасный доступ к аккаунту.*

**Блоки и элементы**

  - Регистрация: имя, почта, пароль, телефон (необязательно), галочка согласия на обработку ПД со ссылкой.

  - Вход: почта и пароль, «Забыли пароль?».

  - Подтверждение почты: письмо со ссылкой; повторная отправка через 60 секунд.

  - Восстановление: почта → письмо со ссылкой (действует 1 час) → новый пароль.

**Правила**

  - Пароль от 8 символов. После 5 неверных попыток — пауза.

  - Без подтверждённой почты можно пройти онбординг, но нельзя оплатить.

  - После регистрации → онбординг; после входа → туда, откуда пришёл.

**События аналитики:** регистрация, подтверждение почты, вход.

### П6. Правовые страницы и ошибки

**Адрес:** /legal/..., /404, /500 **Доступ:** все

*Юридическая обязательность и понятные ошибки.*

**Блоки и элементы**

  - Политика обработки персональных данных, согласие на обработку ПД, оферта на подписку.

  - Страницы 404 и 500 со ссылкой на главную.

## 7.3. Личная часть

### Л1. Онбординг

**Адрес:** /onboarding **Доступ:** пользователь

*Собрать данные для плана за 1 минуту.*

**Блоки и элементы**

  - Шаг 1. Статус: студент / выпускник / переквалификация / другое; для студента — курс.

  - Шаг 2. Профессия: из списка или «Не знаю».

  - Шаг 3. Часов в неделю (ползунок 2–40) и дедлайн (необязательно).

  - Шаг 4. Короткий вопрос для гипотез: «Сколько месяцев вы уже учитесь?» и «Было ли, что учили лишнее?» (необязательно).

  - Индикатор шагов, кнопка «Назад».

**Действия и переходы**

  - «Не знаю» → профориентация; профессия выбрана → её карточка.

**Правила**

  - Данные можно изменить в профиле.

  - Онбординг можно пропустить — тогда при построении плана спросим часы ещё раз.

**События аналитики:** старт и завершение онбординга, ответы на вопросы гипотез.

### Л2. Профориентация

**Адрес:** /career-test, /career-test/result **Доступ:** пользователь

*Помочь выбрать профессию.*

**Блоки и элементы**

  - 15–20 вопросов: интересы, что нравится делать, отношение к математике, дизайну, общению и т. п.; прогресс-бар.

  - Результат: топ-3 профессии с % совпадения и пояснением «почему подходит»; ссылки на карточки.

**Правила**

  - Подсчёт — по таблице баллов (раздел 8.3), без ИИ, чтобы результат был объяснимым.

  - Результат сохраняется; тест можно пройти заново.

**События аналитики:** старт, завершение, выбор профессии из результата.

### Л3. Оценка навыков

**Адрес:** /assessment/{профессия} **Доступ:** пользователь

*Понять, что человек уже умеет, за 7–10 минут.*

**Блоки и элементы**

  - По каждому ключевому навыку (15–25 на профессию): самооценка «не знаю / базово / уверенно».

  - Для «уверенно» — 1–2 коротких проверочных вопроса.

  - Прогресс-бар, возможность прервать и продолжить позже.

**Правила**

  - Расчёт уровня — раздел 8.4.

  - Повторная оценка — не чаще раза в 7 дней.

**События аналитики:** старт, завершение, время прохождения.

### Л4. Отчёт о разрыве

**Адрес:** /assessment/{профессия}/report **Доступ:** пользователь; полный — подписчик

*Главный «вау-момент»: сколько не хватает до вакансий.*

**Блоки и элементы**

  - Крупно: % соответствия требованиям вакансий junior.

  - Есть / частично / не хватает — с % вакансий у каждого навыка.

  - Краткий: % и топ-3 пробела, остальное размыто с призывом к подписке.

  - Полный: все навыки, примерное время на закрытие пробелов, сравнение с рынком.

  - Оценка полезности отчёта (1–5) и вопрос «Узнали что-то новое?».

**Действия и переходы**

  - Без подписки: «Получить персональный план» → тарифы.

  - С подпиской: «Построить план» → план.

**Правила**

  - В итоговой версии отчёт — всплывающее окно или блок на странице оценки (решили 06.10).

**События аналитики:** просмотр отчёта, оценка полезности, клик «Получить план».

### Л5. Персональный план

**Адрес:** /plan/{профессия} **Доступ:** подписчик; заморожено — только чтение

*Конкретно: что, в каком порядке и к какому сроку учить.*

**Блоки и элементы**

  - Сводка: % соответствия сейчас → после плана, всего часов, ожидаемая дата готовности, сравнение с дедлайном.

  - Этапы: блоки тем по порядку; у каждой темы — часы и статус.

  - Проекты: тренировочные после блоков и итоговый пет-проект для портфолио.

  - Пояснение ИИ: почему такой порядок и на что обратить внимание.

  - Отчёт о разрыве (полный) и дата данных о вакансиях.

  - Оценка полезности плана (1–5).

**Состояния**

  - Активный; требует обновления (рынок изменился); заморожен.

**Действия и переходы**

  - Тема → roadmap с открытой темой.

  - «Пройти оценку заново» → оценка.

  - «Обновить план» → новая версия (старая сохраняется).

  - Изменить часы в неделю → пересчёт сроков.

**Правила**

  - Не успевает к дедлайну → предупреждение и варианты: больше часов или убрать необязательные темы.

  - Как строится план — раздел 8.7.

**События аналитики:** построение плана, обновление, оценка полезности.

# 8\. Ключевые механизмы

## 8.1. Контент: профессии, темы, навыки, ресурсы

  - **Профессия** состоит из блоков, блок — из тем.

  - **Тема** связана с одним или несколькими навыками; у темы есть краткое описание, оценка времени (часы с нуля), темы-предшественники, ресурсы и признак «не обязательно для junior».

  - **Навык** хранится один раз и может относиться к нескольким профессиям (например, Git). У навыка есть синонимы — чтобы «JS», «JavaScript» и «ЯваСкрипт» из вакансий считались одним навыком.

  - **Ресурс:** название, ссылка, тип (статья, видео, курс, документация, практика), язык, бесплатный или платный, дата проверки ссылки.

  - **Новые ресурсы попадают в справочник только после ручной проверки командой (раздел 9.1). Материалы, которые предложил ИИ, пользователь не видит, пока их не одобрили.**

  - **Проекты:** библиотека тренировочных и пет-проектов, каждый закрывает набор тем.

  - Всё редактируется в админке без программиста.

## 8.2. Данные о вакансиях

Это ядро продукта и наша «работа с большими данными».

1.  **Сбор:** вакансии из нескольких источников — SuperJob API, «Работа России», Telegram-каналы с вакансиями; hh.ru — после получения партнёрского доступа к API (подробно — раздел 10.3). Только Россия, опыт «нет опыта» и «1–3 года».

2.  Отнесение к профессии: по названию и профобласти вакансии, спорные — на ручную проверку.

3.  Извлечение навыков: поле «ключевые навыки» + поиск навыков в тексте вакансии по справочнику и синонимам (без языковой модели).

4.  Нормализация: сопоставление со справочником навыков по синонимам; новые незнакомые термины (часто встречаются, но нет в справочнике) — в админку на проверку.

5.  Расчёт веса навыка: доля вакансий профессии, где он упоминается.

6.  Проверка и публикация: админ смотрит изменения и публикует новые веса.

7.  История: веса хранятся по месяцам — можно показать, как меняется спрос на навык.

8.  Хранение: сырые тексты вакансий храним 12 месяцев — для истории весов и проверки расчётов.

**Правила: обновление раз в месяц; не меньше 200 вакансий на профессию за период, иначе показываем «мало данных»; навыки с весом меньше 5% не учитываем как обязательные; одна и та же вакансия из разных источников считается один раз (склейка дубликатов).**

## 8.3. Профориентация

  - Каждый вариант ответа добавляет баллы профессиям по заранее составленной таблице.

  - Итог: % совпадения = баллы профессии ÷ максимально возможные баллы; показываем топ-3.

  - Баллы пользователю не показываем: он видит только % совпадения и топ-3 профессии. Баллы нужны только для расчёта.

  - Пояснение «почему подходит» — по ответам, которые дали больше всего баллов.

  - Профессии «Скоро» тоже могут попасть в топ-3 — тогда предлагаем «Сообщить о запуске».

## 8.4. Оценка навыков

|                                      |                    |
| ------------------------------------ | ------------------ |
| **Ответ**                            | **Уровень навыка** |
| Не знаю                              | 0                  |
| Базово                               | 0,5                |
| Уверенно + проверочные вопросы верно | 1                  |
| Уверенно, но проверка не пройдена    | 0,5                |

## 8.5. Соответствие вакансиям

|                                                                                                  |
| ------------------------------------------------------------------------------------------------ |
| **% соответствия =** сумма (вес навыка × уровень) ÷ сумма весов всех обязательных навыков × 100% |

Пример: если пользователь уверенно знает навыки, которые встречаются в половине «веса» вакансий, его соответствие — 50%.

## 8.6. Отчёт о разрыве

  - **Краткий:** % соответствия и 3 пробела с самым большим весом.

  - **Полный:** все навыки по группам «есть / частично / нет», % вакансий, часы на закрытие, дата данных.

## 8.7. Персональный план и роль ИИ

План строит ИИ по алгоритму, заданному в промпте, с учётом данных пользователя: уровни навыков, часы в неделю, дедлайн, цель. Ответ ИИ проверяется по справочнику — это защищает от выдуманных навыков и ссылок. Алгоритм:

1.  Берём навыки с уровнем ниже 1 и их темы.

2.  Сортируем: сначала темы-предшественники, затем по весу навыка в вакансиях.

3.  Считаем часы: с нуля — полное время, «базово» — половина.

4.  Раскладываем по неделям с учётом часов в неделю → дата готовности; сравниваем с дедлайном.

5.  После каждого блока вставляем тренировочный проект, в конце — пет-проект из библиотеки.

6.  ИИ подстраивает план под пользователя внутри допустимого порядка и пишет пояснения к шагам.

7.  Проверка: ИИ может ссылаться только на темы, навыки и ресурсы из справочника; всё лишнее отбрасывается.

Если ИИ недоступен — запасной план строится тем же алгоритмом в коде, без пояснений. Каждая версия плана сохраняется. Промпт с алгоритмом разрабатываем позже.

## 8.8. Прогресс

  - «Изучено» — отметка самого пользователя.

  - Прогресс плана = изученные часы ÷ все часы плана.

  - Когда изучены все темы навыка, его уровень становится 1 и растёт % соответствия вакансиям.

  - «Текущий шаг» — первая неизученная тема по порядку плана.

## 8.10. Заморозка (подписка закончилась)

  - Персональный план и персональный roadmap — только чтение: ничего нельзя нажать или отметить.

  - Полный отчёт и сводка по рынку скрыты, остаётся краткий отчёт.

  - Весь прогресс и версии планов сохраняются.

  - При продлении всё продолжается с того же места.

## 8.11. Несколько профессий

  - Количество планов не ограничено: пользователь берёт столько профессий, сколько хочет учить. Создание и пересборка планов ограничены дневным лимитом запросов к ИИ (раздел 11).

  - У каждой профессии своя оценка, отчёт, план и прогресс.

  - Общие навыки (например, Git) засчитываются во всех профессиях.

## 9.1. Новые навыки и проверка материалов

**Отдельный блок админки, куда попадают все новые навыки. Задача блока — чтобы ни один курс, видео или статья не дошли до пользователя без проверки командой.**

  - **Откуда появляется навык: из вакансий (при загрузке система нашла навык, которого нет в справочнике, — раздел 8.2) или команда добавила его вручную.**

  - **Предложение ИИ: ИИ подбирает к новому навыку материалы — курсы, видео, статьи, документацию. Это только предложение: у материалов статус «Предложено ИИ».**

  - **Ручная проверка: член команды открывает каждый материал, просматривает его и решает: одобрить, заменить своим (вручную вставить другую ссылку) или отклонить. Можно добавить свои материалы и оставить комментарий.**

  - **Публикация: пользователи видят только одобренные материалы. Пока навык не проверен, он есть в справочнике, но без ресурсов.**

# 11\. Требования к качеству

  - **Персональные данные:** хранение на серверах в России, согласие при регистрации, отзыв согласия и удаление аккаунта, политика на сайте. Нужно ли уведомлять Роскомнадзор об обработке ПД — уточнить (у юриста или в вузе).

  - **Безопасность:** только HTTPS, пароли в виде хеша, защита от перебора пароля, роли доступа, резервные копии базы ежедневно.

  - **Скорость:** страница открывается быстрее 2 секунд; построение плана — до 30 секунд с индикатором.

  - **Браузеры:** последние версии Chrome, Яндекс Браузера, Firefox, Edge, Safari, Opera.

  - **ИИ:** дневной лимит на создание и пересборку планов (раздел 8.11); при недоступности — запасной план без ИИ (раздел 8.7); только отечественные модели, данные остаются в России; модель подключается через заменяемый слой. Основная — YandexGPT 5.1 Pro (Yandex AI Studio), запасная — предварительно GigaChat 2 Pro (Сбер).

  - **Стек:** бэкенд — Go (gin), модульный монолит + отдельный воркер для фоновых задач (запросы к ИИ, письма); сбор и анализ вакансий — отдельный модуль на Python (сбор с бирж и Telegram, поиск навыков, расчёт весов), общается с бэкендом через общую базу; фронтенд — React + TypeScript + Vite (SPA), API описан в OpenAPI; база данных — PostgreSQL; хостинг — российский (выбираем).

  - **Надёжность:** журнал ошибок; оповещение команды о падении сайта.

  - **Для Роспатента:** код в репозитории с историей; документация по модулям.

  - Лента новостей и трендов по навыкам профессии.
