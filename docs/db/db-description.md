База данных «Карьерного навигатора IT»

Описание схемы для разработки. Версия от 10.10.2026. PostgreSQL 16.

*Документ — справочник для Юрия и Claude: что хранится в каждой таблице, как таблицы связаны и какие решения приняты. Источник истины — файл бд\_схема.dbml; при изменениях сначала правим его, затем пересобираем SQL, схемы и этот документ.*

1\. Общие правила

  - **СУБД:** PostgreSQL 16. Расширение citext — для почты, промокодов и синонимов без учёта регистра.

  - **Ключи:** bigint GENERATED ALWAYS AS IDENTITY. Наружу id пользователей не показываем, в адресах страниц — slug.

  - **Время:** timestamptz везде; даты без времени (дедлайн, период снимка) — date.

  - **Статусы и типы:** text с ограничением CHECK (... IN (...)). Список допустимых значений указан в описании поля. Так проще добавлять значения миграцией, чем с enum.

  - **Деньги:** целые рубли (int), стоимость ИИ — numeric(10,4).

  - **Связи многие-ко-многим:** отдельные таблицы с составным первичным ключом (например, topic\_skills).

  - **Персональные данные:** база размещается только на российском хостинге (152-ФЗ, ч. 5 ст. 18).

1.2. Принятые решения

  - Темы — общая библиотека (topics), в профессии ставятся через block\_topics. Порядок и «необязательно для junior» задаются отдельно для каждой профессии.

  - Уровень навыка пользователя общий для всех профессий (user\_skill\_levels). Отметки «Изучено» тоже общие (topic\_progress).

  - Отчёт о разрыве не хранится: считается из оценки (assessment\_answers) и весов навыков (skill\_weights). В assessments сохраняется только итоговый %.

  - План версионируется: plans → plan\_versions → plan\_items. Старые версии не удаляются.

  - Один план на профессию (уникальность user\_id + profession\_id), количество профессий не ограничено. Создание и пересборка ограничены дневным лимитом запросов к ИИ (ai\_requests).

  - Баллы профориентации скрыты (career\_option\_scores), пользователь видит только % совпадения и топ-3.

  - Навыки в вакансиях ищутся по справочнику и синонимам, без языковой модели. Незнакомые частые термины — в unknown\_terms на проверку.

  - Материалы от ИИ попадают в resources со статусом ai\_suggested; пользователь видит только approved.

  - Удаление аккаунта: личные данные удаляются каскадом, платежи остаются с пустым user\_id.

  - Сырые вакансии храним 12 месяцев (очистка — задачей модуля сбора вакансий на Python).

1.4. Правила удаления связанных записей

При удалении записи, на которую ссылаются, PostgreSQL поступает так:

|                                |                                                                                                                                                                                              |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Правило**                    | **Где применяется**                                                                                                                                                                          |
| CASCADE — удалить вместе       | Все личные данные пользователя (user\_id) кроме платежей; таблицы-связки и дочерние записи (blocks, block\_topics, plan\_versions, plan\_items, assessment\_answers, skill\_weights и т. п.) |
| SET NULL — обнулить ссылку     | payments.user\_id; reviewed\_by и published\_by (кто из команды проверил или опубликовал)                                                                                                    |
| Запрет удаления (по умолчанию) | Остальные связи: например, нельзя удалить профессию, по которой есть оценки или планы; нельзя удалить администратора, у которого есть записи в audit\_log                                    |

2\. Ключевые потоки данных

  - **Вакансии → веса навыков.** import\_runs загружает vacancies; vacancy\_skills заполняется поиском по skills и skill\_synonyms; незнакомые термины — в unknown\_terms. Раз в месяц по каждой профессии считается weight\_snapshots + skill\_weights (не меньше 200 вакансий), администратор публикует снимок.

  - **Оценка → % соответствия.** assessment\_answers.level (0 / 0,5 / 1) × skill\_weights.weight по обязательным навыкам ÷ сумма весов × 100%. Результат — в assessments.match\_percent, уровни — в user\_skill\_levels.

  - **План.** Навыки с уровнем ниже 1 → их темы (topic\_skills, block\_topics) с учётом topic\_prerequisites → часы, недели, проекты (project\_topics). ИИ строит план по алгоритму из промпта; результат проверяется по справочнику и сохраняется как plan\_versions + plan\_items; запрос пишется в ai\_requests.

  - **Прогресс.** «Изучено» → topic\_progress. Когда изучены все темы навыка, user\_skill\_levels.level = 1 и растёт % соответствия.

  - **Подписка.** Оплата создаёт subscriptions (pending) и payments; по подтверждению сервиса — active. Неудачное автосписание → past\_due, через 3 дня → frozen. Промокод создаёт подписку с source = promo.

  - **Новые навыки (раздел 9.1 структуры).** unknown\_terms → skills (status new) → ИИ предлагает resources (ai\_suggested) через resource\_skills → команда одобряет или заменяет → topic\_resources.
