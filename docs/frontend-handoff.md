# Фронтенд: стандарты и требования (для Евгения)

> Статус: **финальная версия по срезу 1** (07.11.2026). Всё, что описано ниже, работает на реальном backend и проверено запросами. Контракт — `api/openapi.yaml` (OpenAPI 3.1, проходит Redocly lint): если документ и спецификация расходятся, верна спецификация.

## 1. Твой сервис в общей схеме

Платформа — три сервиса, каждый в своей папке и своём контейнере:

| Сервис | Папка | Кто | Что делает |
|---|---|---|---|
| backend (Go) | `backend/` | Юрий | API для фронтенда: аккаунт, контент, «Изучено», оценка, % соответствия, отчёт, план, админка; фоновый воркер |
| аналитика (Python) | `collector/` | Юрий | Сбор вакансий (SuperJob, «Работа России»), поиск навыков, веса навыков — по расписанию. С фронтендом не общается |
| **frontend (React)** | `frontend/` | **Евгений** | SPA: все экраны для пользователя и админки |

Фронтенд общается **только с backend по HTTP** через `/api/v1/...`. В базу и в сервис аналитики напрямую не ходит.

Репозитории: общий — `github.com/kayeros/IT-career-navigator`, твоя папка — `frontend/` (и прототип `index.html` в корне). Бэкенд, аналитику, `api/`, `docs/` и `docker-compose.yml` туда выгружает Юрий из своего рабочего репозитория — эти пути не правь, иначе правки перезапишутся при следующей выгрузке. Нужна правка — пиши Юрию или заводи issue.

## 2. Стек

- React + TypeScript (strict) + Vite, SPA.
- Типы API генерируются из `api/openapi.yaml` командой (`npm run gen:api`), руками не пишутся. Рекомендуем: `openapi-typescript` + `openapi-fetch`.
- Роутинг: `react-router`.
- UI-библиотека, стили, работа с формами — на твой выбор. Условие: без внешних CDN и подгрузки шрифтов/скриптов со сторонних серверов (152-ФЗ). Шрифты — локально в проекте.
- Аналитика и счётчики (Яндекс Метрика и т. п.) — не подключаем без согласования.
- Новую крупную зависимость (state-менеджер, UI-кит) — сначала напиши Юрию.

## 3. Структура и запуск

```
frontend/
  src/
    api/        сгенерированные типы и клиент (не править руками)
    pages/      страницы по карте экранов
    components/ общие компоненты
    ...
  .env.example  VITE_API_BASE=/api/v1
  Dockerfile    сборка → nginx отдаёт dist/
  nginx.conf    SPA + прокси /api на backend
```

Backend и база локально (из корня общего репозитория):

```bash
docker compose up --build -d db api worker collector
docker compose exec api /app/api seed
```

- `.env` не обязателен: без него берутся значения по умолчанию. Проверка: `http://localhost:8080/health` → `{"status":"ok","db":"ok"}`.
- `api seed` загружает черновик контента 3 профессий (QA, Python, Java) и проверочные вопросы. Повторный запуск безопасен.
- Вакансии и веса навыков: `docker compose run --rm collector run-all` (загрузит «Работу России»; SuperJob — когда в `.env` будет ключ). Без этого шага % соответствия возвращает пустое состояние (см. 4.4) — так и должно быть.
- В Git Bash перед `docker compose exec ... /app/...` нужен `MSYS_NO_PATHCONV=1`.

Фронтенд локально: `npm run dev`, Vite проксирует `/api` на `http://localhost:8080` — так cookie сессии работает без CORS:

```ts
server: { port: 5173, proxy: { "/api": { target: "http://localhost:8080", changeOrigin: false } } }
```

В Docker: `frontend/Dockerfile` (сборка `node:22-alpine` → `nginx:alpine`) и `frontend/nginx.conf` с `location /api/ { proxy_pass http://api:8080; }` и `try_files $uri /index.html` для остальных путей. Сервис `frontend` в `docker-compose.yml` добавляет Юрий, когда Dockerfile готов (предлагаемый порт — `3000:80`).

Команды: `npm run dev`, `npm run build`, `npm run gen:api`, `npm run lint`.

## 4. Работа с API

### 4.1. Общие правила

- Базовый путь — `/api/v1`. Только относительные пути от `VITE_API_BASE`.
- **Все запросы — с `credentials: 'include'`.** Тело — JSON. Ответ `204` — без тела.
- Даты: `2026-11-01` (дата) и `2026-11-05T19:05:02Z` (момент). Показываем «5 ноября 2026».

### 4.2. Сессия

| Параметр | Значение |
|---|---|
| Cookie | `session` — httpOnly, `SameSite=Lax`, `Path=/`, `Secure` везде, кроме локальной среды |
| Срок | 30 дней |
| Ставится | ответами `POST /auth/register` (сразу вход) и `POST /auth/login` |
| Стирается | `POST /auth/logout`; после смены пароля по ссылке все сессии закрываются |
| Кто вошёл | `GET /me` → `200` пользователь / `401` гость |
| Сессия истекла | любой защищённый запрос → `401` → сбросить пользователя, показать вход, после входа вернуть на ту же страницу |

Токены в `localStorage`/`sessionStorage` не храним и в JS не читаем.

### 4.3. Ошибки

Формат всегда один:

```json
{ "error": { "code": "validation_error", "message": "Проверьте поля формы",
             "fields": { "password": "Пароль должен быть от 8 до 128 символов" } } }
```

Логику ветвим **только по `code`**; `message` можно показать как есть; `fields` — ошибки под полями формы.

| HTTP | code | Когда | Что делает фронтенд |
|---|---|---|---|
| 400 | `validation_error` | ошибка в данных | тексты из `fields` под полями |
| 400 | `invalid_token` | ссылка из письма неверная, устарела или использована | сообщение + «Запросить новую ссылку» |
| 401 | `invalid_credentials` | неверная почта или пароль | общее сообщение над формой |
| 401 | `unauthorized` | не вошёл / сессия истекла | показать вход |
| 403 | `forbidden` | нет роли admin | «Нет доступа» |
| 404 | `not_found` | нет профессии, темы, оценки, плана | страница «Не найдено» / пустое состояние |
| 409 | `email_taken` | почта уже зарегистрирована | ошибка у поля «Почта» + ссылка «Войти» |
| 409 | `already_verified` | почта уже подтверждена | убрать баннер |
| 409 | `too_soon` | повторная оценка раньше 7 дней | `message` содержит дату, когда можно |
| 409 | `completed` | ответ в завершённую оценку | перейти к отчёту |
| 409 | `conflict` | админка: такой slug, название или синоним уже есть | ошибка у поля |
| 429 | `too_many_attempts` | 5 неудачных входов за 15 минут | сообщение, кнопка неактивна `Retry-After` секунд |
| 429 | `too_many_requests` | письмо подтверждения чаще раза в минуту | таймер по `Retry-After` |
| 500 | `internal` | сбой сервера | «Что-то пошло не так, попробуйте позже» |

### 4.4. Эндпоинты

Все пути — от `/api/v1`. «Вход»: нет — открыт всем; да — нужна сессия; admin — роль admin.

**Аккаунт**

| Метод и путь | Вход | Ответ |
|---|---|---|
| `POST /auth/register` `{name, email, password, consent_pd: true, consent_marketing?}` | нет | `201` User + cookie; `400`, `409 email_taken` |
| `POST /auth/login` `{email, password}` | нет | `200` User + cookie; `400`, `401`, `429` |
| `POST /auth/logout` | нет | `204` |
| `GET /me` | да | `200` User `{id, email, name, role, email_verified}` |
| `POST /auth/verify-email` `{token}` | нет | `204`; `400 invalid_token` |
| `POST /auth/verify-email/resend` | да | `204`; `409 already_verified`; `429` |
| `POST /auth/password-reset` `{email}` | нет | `204` всегда (не выдаём, есть ли такая почта) |
| `POST /auth/password-reset/confirm` `{token, password}` | нет | `204` (все сессии закрыты — нужен вход); `400` |

Ссылки из писем ведут на страницы фронтенда: **`/verify-email?token=…`** и **`/reset-password?token=…`** — эти два маршрута нужны в SPA: взять `token` из адреса и отправить в API. Пока почтового сервиса нет, письма пишутся в журнал backend (`docker compose logs api`).

**Онбординг и профиль**

| Метод и путь | Вход | Ответ |
|---|---|---|
| `GET /me/profile` | да | `200` Profile (поля `null`, пока не заполнены) |
| `PUT /me/profile` `{learner_status?, course?, hours_per_week? (2–40), deadline?, months_learning?, learned_unneeded?, complete_onboarding?}` | да | `200` Profile; передаются только изменяемые поля |

Выбор профессии в онбординге не хранится: «Не знаю» → профориентация (будет позже), профессия выбрана → её карточка.

**Каталог, roadmap, «Изучено»**

| Метод и путь | Вход | Ответ |
|---|---|---|
| `GET /professions` | нет | `200 {items: ProfessionSummary[]}` |
| `GET /professions/{slug}` | нет* | `200` блоки → темы → материалы, `progress` (null для гостя); `404` |
| `PUT /topics/{id}/progress` / `DELETE` | да | `204` |
| `POST /waitlist` `{profession_slug, email?}` | нет | `204` («Сообщить о запуске»; вошедшему почту можно не передавать) |

**Оценка навыков → отчёт**

| Метод и путь | Вход | Ответ |
|---|---|---|
| `POST /professions/{slug}/assessments` | да | `201` новая / `200` незавершённая; `409 too_soon` |
| `GET /assessments/{id}` | да | `200` Assessment |
| `PUT /assessments/{id}/answers/{skill_id}` `{self_level: none\|basic\|confident, check_option?}` | да | `200` навык с ответом; `400` (для «уверенно» нужен `check_option`) |
| `POST /assessments/{id}/complete` | да | `200` Report (краткий отчёт); `400`, если ответили не на всё |
| `GET /professions/{slug}/report` | да | `200` Report |
| `GET /professions/{slug}/match` | да | `200` Match (% и топ-5 недостающих навыков) |

Assessment: `skills[]` — ключевые навыки по убыванию важности; у навыка `question` `{id, text, options[]}` (показывать, когда выбрано «уверенно») и `answer` (`null`, пока не ответил). Верный вариант знает только сервер; проверочный вопрос засчитывается один раз — переответить нельзя. Прервать и продолжить можно: `POST …/assessments` вернёт ту же незавершённую оценку.

Report:

```json
{ "percent": 32.4,
  "snapshot": { "period": "2026-11-01", "vacancy_count": 39, "calculated_at": "…", "preliminary": true },
  "assessment": { "id": 1, "completed_at": "2026-11-07T15:30:31Z" },
  "counts": { "have": 1, "partial": 1, "missing": 23 },
  "top_gaps": [ { "skill_id": 17, "name": "Jira", "weight": 0.64, "level": 0.5,
                  "topics": [ { "id": 15, "slug": "qa-jira", "title": "Jira и трекеры задач", "studied": false } ] } ] }
```

- `percent: null`, `snapshot: null` — данных о вакансиях ещё нет → «Данные о вакансиях ещё собираются».
- `preliminary: true` — меньше 200 вакансий → пометка «Предварительная оценка».
- `weight` — доля вакансий: `0.64` → «нужен в 64% вакансий»; `level` `0.5` — «частично».
- Краткий отчёт: % + группы «есть / частично / не хватает» + топ-3 пробела. Полный — по подписке (позже), сейчас показываем краткий, остальное размыто с призывом.

**План «что учить дальше»**

| Метод и путь | Вход | Ответ |
|---|---|---|
| `POST /professions/{slug}/plan` `{hours_per_week?, deadline?}` | да | `201` Plan — новая версия (прежние сохраняются); `400`, если часов нет ни в запросе, ни в профиле |
| `GET /professions/{slug}/plan` | да | `200` Plan; `404`, если плана ещё нет |

Plan: `total_hours`, `ready_date`, `late` + `hours_per_week_needed` (не успевает к дедлайну — предложить больше часов), `match_before` → `match_after`, `progress {studied_hours, total_hours, percent}`, `current_item_id` (текущий шаг), `items[]` `{topic {id, slug, title}, hours, week_no, status: to_learn|optional, studied, skills[]}`. Отметки «Изучено» в плане — те же `PUT/DELETE /topics/{id}/progress`. Сейчас план доступен всем вошедшим; после запуска подписки — только подписчикам.

**Админка (роль admin)** — `/admin/...`: профессии (`GET/POST`, `PATCH /{id}`), блоки (`GET/POST /professions/{id}/blocks`, `PATCH/DELETE /blocks/{id}`, `PUT /blocks/{id}/topics`), навыки профессии (`GET/PUT /professions/{id}/skills`), темы (`GET ?q=`, `POST`, `PATCH /{id}`, `PUT /{id}/skills`, `PUT /{id}/resources`), навыки (`GET ?status=`, `POST`, `PATCH /{id}`), синонимы (`POST /skills/{id}/synonyms`, `DELETE /synonyms/{id}`), материалы (`GET ?status=`, `POST`, `PATCH /{id}` — одобрить / отклонить / заменить), заявки «Сообщить о запуске» (`GET /admin/waitlist`), новые термины из вакансий (`GET /admin/unknown-terms`, `PATCH /{id}` — сделать навыком, синонимом или игнорировать). Все изменения пишутся в журнал. Поля и схемы — в `api/openapi.yaml`, тег `admin`.

## 6. Требования

- Браузеры: последние Chrome, Яндекс Браузер, Firefox, Edge, Safari, Opera.
- Для MVP — ПК (от 1280 px). Адаптив под телефон — к этапу 3, но вёрстку сразу делаем без жёстких ширин.
- Страница открывается быстрее 2 с; на долгих действиях — индикатор загрузки, кнопки блокируются от двойного нажатия.
- Все тексты — на русском. Ошибки формы — у конкретного поля.
- Доступность: у полей есть подписи, кнопки нажимаются с клавиатуры, контраст текста читаемый.
- Пользователь видит только одобренные материалы — фронтенд показывает то, что пришло из API, ничего не фильтрует и не добавляет сам.
- Баллы профориентации и внутренние веса не показываем — только то, что API отдаёт для показа.

## 7. Как работаем

- Код — в общем репозитории, папка `frontend/`. Ветка на задачу, в `main` — через pull request; сообщения коммитов — на русском.
- Задачи и статусы — в Notion (база «Задачи», направление «Сайт/прототип»).
- Изменения контракта API — только через Юрия: сначала меняется `api/openapi.yaml`, затем ты перегенерируешь типы.
- Готово, когда: экран работает на реальном API в `docker compose up`, `npm run build` и `npm run lint` проходят, путь проверен руками в Chrome и ещё одном браузере.

## 8. Тестовые данные и учётки

- Контент: `docker compose exec api /app/api seed` — 3 профессии, 52 темы, 57 навыков, проверочные вопросы. Это **черновик**: Рустам правит темы, навыки и вопросы, Алик — материалы. `slug` тем стабилен, названия могут меняться.
- Пользователь: регистрируйся через свою форму на localhost (почта вида `ты@example.test`). Ссылки подтверждения и сброса — в `docker compose logs api`.
- Админ: зарегистрируйся, затем `docker compose exec api /app/api create-admin ты@example.test`.
- Вакансии и веса: `docker compose run --rm collector run-all`.
- Временная демо-страница backend `http://localhost:8080/demo/` (только локально) показывает рабочие вызовы среза 0 — после подключения SPA её удалим.
