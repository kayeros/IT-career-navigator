# Фронтенд: стандарты и требования (для Евгения)

> Статус: **черновик**. Финальную версию собирает Claude Code, когда backend и сервис аналитики закроют срез 1 из `docs/mvp-plan.md`. Разделы с пометкой «заполнить по факту» заполняются по работающему API, а не по ожиданиям.

## 1. Твой сервис в общей схеме

Платформа — три сервиса, каждый в своей папке и своём контейнере:

| Сервис | Папка | Кто | Что делает |
|---|---|---|---|
| backend (Go) | `backend/` | Юрий | API для фронтенда, аккаунт, контент, % соответствия, план; фоновый воркер |
| аналитика (Python) | `collector/` | Юрий | Сбор вакансий, поиск навыков, веса навыков. С фронтендом не общается |
| **frontend (React)** | `frontend/` | **Евгений** | SPA: все экраны для пользователя и админки |

Фронтенд общается **только с backend по HTTP** через `/api/v1/...`. В базу и в сервис аналитики напрямую не ходит.

Контракт — `api/openapi.yaml`. Это источник истины: если в спецификации и в ответе API расходятся — пиши Юрию, не подстраивайся молча.

## 2. Стек

- React + TypeScript (strict) + Vite, SPA.
- Типы API генерируются из `api/openapi.yaml` командой (`npm run gen:api`), руками не пишутся. Предложение: `openapi-typescript` + `openapi-fetch`.
- Роутинг: `react-router`.
- UI-библиотека, стили, работа с формами — на твой выбор. Условие: без внешних CDN и подгрузки шрифтов/скриптов со сторонних серверов (152-ФЗ, данные пользователей из РФ). Шрифты — локально в проекте.
- Аналитика и счётчики (Яндекс Метрика и т. п.) — не подключаем без согласования.
- Новую крупную зависимость (state-менеджер, UI-кит) — сначала напиши Юрию.

## 3. Структура и запуск

```
frontend/
  src/
    api/        сгенерированные типы и клиент (не править руками)
    pages/      страницы по карте экранов
    components/ общие компоненты
    ...
  .env.example  VITE_API_BASE=/api/v1
  Dockerfile    сборка → nginx отдаёт dist/
```

- Локально: `npm run dev`, Vite проксирует `/api` на `http://localhost:8080` — так cookie сессии работают без CORS.
- В Docker: сервис `frontend` в общем `docker-compose.yml` (заполнить по факту: порт и команда).
- Команды: `npm run dev`, `npm run build`, `npm run gen:api`, `npm run lint`.

## 4. Работа с API

- Базовый путь: `/api/v1`. (Заполнить по факту: полный список эндпоинтов MVP с примерами запроса и ответа.)
- **Авторизация — cookie-сессия** (httpOnly). Токены в `localStorage`/`sessionStorage` не храним и в JS не читаем. Все запросы — с `credentials: 'include'`.
- `GET /api/v1/me` — кто вошёл; `401` → пользователь не вошёл, показываем вход.
- Формат ошибки (заполнить по факту, ожидается):
  ```json
  { "error": { "code": "email_taken", "message": "Почта уже зарегистрирована" } }
  ```
  `message` можно показывать пользователю как есть, ветвление логики — только по `code`.
- Коды: `400` — ошибка в данных (подсветить поле), `401` — не вошёл, `403` — нет прав (админка), `404` — нет страницы/профессии, `429` — слишком много попыток входа, `5xx` — общее сообщение «Что-то пошло не так, попробуйте позже».
- Пока эндпоинта нет — работаешь на моках по спецификации, не ждёшь бэкенд.

## 5. Экраны MVP

Карта экранов — `docs/design/screen-map.html`, структура — `docs/product/structure.md`. Для MVP нужны:

| Экран | Что на нём | API (заполнить по факту) |

Админка контента — после MVP, отдельным списком.

## 6. Требования

- Браузеры: последние Chrome, Яндекс Браузер, Firefox, Edge, Safari, Opera.
- Для MVP — ПК (от 1280 px). Адаптив под телефон — к этапу 3, но вёрстку сразу делаем без жёстких ширин, чтобы потом не переписывать.
- Страница открывается быстрее 2 с; на долгих действиях — индикатор загрузки, кнопки блокируются от двойного нажатия.
- Все тексты — на русском. Ошибки формы — у конкретного поля.
- Доступность: у полей есть подписи, кнопки нажимаются с клавиатуры, контраст текста читаемый.
- Пользователь видит только одобренные материалы — фронтенд показывает то, что пришло из API, ничего не фильтрует и не добавляет сам.
- Баллы профориентации и внутренние веса не показываем — только то, что API отдаёт для показа.

## 7. Как работаем

- Код — в общем репозитории, папка `frontend/`. Ветка на задачу, сообщения коммитов — на русском.
- Задачи и статусы — в Notion (база «Задачи», направление «Сайт/прототип»).
- Изменения контракта API — только через Юрия: сначала меняется `api/openapi.yaml`, затем ты перегенерируешь типы.
- Готово, когда: экран работает на реальном API в `docker compose up`, `npm run build` и `npm run lint` проходят, путь проверен руками в Chrome и ещё одном браузере.
