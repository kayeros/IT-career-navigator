# План MVP «Карьерный навигатор IT»

Составлен 05.11.2026. Главный документ на ближайшие недели: по нему работаем по порядку, сверху вниз. Задачи и статусы для команды — в Notion (база «Задачи»), здесь — состав работ и критерии готовности для разработки.

## Что такое MVP для нас

Путь одного студента от начала до конца, который можно показать вживую на демо-дне:

1. Регистрация и вход.
2. Каталог: 3 доступные профессии — ручное тестирование (QA), Python-разработчик, Java-разработчик.
3. Карточка профессии: roadmap по блокам и темам, у тем — проверенные материалы, отметка «Изучено».
4. **% соответствия вакансиям:** сколько навыков из реальных вакансий человек уже закрыл и каких не хватает (топ недостающих навыков с долей вакансий, где они нужны).
5. Простой план «что учить дальше» — без языковой модели, резервным алгоритмом (недостающие навыки по убыванию веса → темы, которые их закрывают, с учётом порядка в roadmap).

ИИ-план, подписка, профориентация, письма, адаптив — после MVP (этап 3). Не начинай их, пока пункты 1–5 не работают от начала до конца.

## Срез 0 — демо трекеру (делаем в этом порядке)

Порядок выбран так, чтобы в любой момент было что показать. Каждый шаг — законченный, проверяемый.

0. **Git.** Если `Code/` ещё не репозиторий — `git init`, `.gitignore` уже есть, первый коммит «Каркас: api, worker, docs». Дальше — коммит после каждого шага (история нужна для Роспатента).
1. **Миграции (goose).** Таблицы аккаунта: `users`, `sessions`, `auth_tokens`, `consents`. Таблицы контента: `professions`, `blocks`, `topics`, `block_topics`, `skills`, `skill_synonyms`, `topic_skills`, `profession_skills`, `resources`, `topic_resources`. Прогресс: `topic_progress`. Вакансии: `vacancy_sources`, `import_runs`, `vacancies`, `vacancy_skills`, `unknown_terms`, `weight_snapshots`, `skill_weights`. Имена и поля — строго как в `docs/db/schema.sql`. Миграции накатываются при старте api (или отдельной командой `api migrate`).
   *Готово, когда:* `docker compose up --build` на чистой базе создаёт таблицы, повторный запуск ничего не ломает.
2. **Seed-контент 3 профессий** (`backend/migrations/seed/` или отдельная команда `api seed`, идемпотентно):
   - профессии: `qa-manual`, `python-developer`, `java-developer` — статус `available`;
   - на каждую 4–6 блоков, 15–25 тем, 15–25 ключевых навыков (`profession_skills.is_key = true`) с синонимами (рус./англ. написания, частые сокращения: «автотесты», «postgres», «постгрес»);
   - общие темы (Git, SQL, HTTP, Linux, основы ООП) — один раз в `topics`, ставятся в блоки разных профессий;
   - материалы — только бесплатные и официальные (документация, открытые курсы вузов, Stepik бесплатные); статус `approved`, в `review_comment` пометка «черновик, проверить Алику».
   *Это черновик для показа.* Рустам правит темы и навыки, Алик — материалы. Сделай файл seed удобным для правки человеком (YAML/JSON по профессиям), а не SQL-простынёй.
3. **OpenAPI** `api/openapi.yaml` (OpenAPI 3.1) на эндпоинты среза 0 — сначала спецификация, потом код.
4. **Аккаунт:** `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, `GET /api/v1/me`.
   - Пароль — argon2id (`golang.org/x/crypto/argon2`). Сессия — непрозрачный токен в httpOnly-cookie (`Secure` вне local, `SameSite=Lax`), в БД только хеш (`sessions.refresh_token_hash`), срок 30 дней. JWT не используем.
   - Согласие на обработку ПД при регистрации обязательно → запись в `consents`.
   - Подтверждение почты: токен в `auth_tokens`, ссылка пишется в журнал (почтового сервиса нет). На срезе 0 вход без подтверждения разрешён.
   - Защита от перебора: простой лимит попыток входа по IP+email в памяти.
5. **Каталог и карточка:** `GET /api/v1/professions` (со статусами), `GET /api/v1/professions/{slug}` (блоки → темы → материалы, у темы — отметка «Изучено» для вошедшего пользователя).
6. **«Изучено»:** `PUT /api/v1/topics/{id}/progress` и `DELETE` того же пути → `topic_progress`. Прогресс по профессии — в ответе карточки (сколько тем изучено из скольких).
7. **Сервис аналитики (`collector/`, Python 3.12):** скелет (psycopg 3, httpx, конфиг из `.env`), контейнер в `docker-compose.yml`, команда `python -m collector load-superjob --profession qa-manual` и `match-skills`, `calc-weights`.
   - Загрузчик SuperJob: поисковые запросы по каждой из 3 профессий, без опыта / до 1 года; пишет `vacancies`, `import_runs`; уникальность (источник, external_id). Ключ — `SUPERJOB_API_KEY` в `.env` (убрать его из Go-воркера).
   - Поиск навыков: по `skills` + `skill_synonyms`, регистронезависимо, по границам слов → `vacancy_skills`. Без языковой модели.
   - Веса: доля вакансий профессии с навыком → `weight_snapshots` + `skill_weights`. **Для MVP разрешаем снимок меньше 200 вакансий**: статус `published`, но в ответе API флаг `preliminary: true`, если вакансий < 200. Это осознанное исключение из правила, записано здесь.
8. **% соответствия:** `GET /api/v1/professions/{slug}/match` для вошедшего пользователя.
   - Уровень навыка на срезе 0 — из «Изучено»: изучены все темы, закрывающие навык (`topic_skills`) → 1; часть → 0,5; ни одной → 0. (Самооценка и проверочные вопросы — срез 1.)
   - % = Σ(вес × уровень) / Σ весов по ключевым навыкам профессии, по последнему опубликованному снимку.
   - В ответе: процент, число вакансий в снимке, дата, `preliminary`, топ-5 недостающих навыков с весом («нужен в 64% вакансий») и темы, которые их закрывают.
9. **Показ, если фронтенд Жени ещё не готов.** Временная демо-страница: один статический HTML+JS без сборки, который отдаёт api по `/demo/` **только при `APP_ENV=local`** (папка `backend/internal/demo/static`, `embed`). Регистрация → каталог → карточка с «Изучено» → блок «% соответствия». Это не фронтенд продукта: после готовности SPA Жени папку удаляем. Если у Жени есть рабочие экраны — подключаем их к API вместо демо-страницы.

Если не успеваем всё: обязательно 0–6 и 9; затем 7–8. На созвоне честно говорим, что сделано и что к 20.11.

## Срез 1 — рабочий MVP к 20.11

По порядку, каждый пункт — отдельная задача и коммит:

1. Подтверждение почты и сброс пароля (`auth_tokens`, письма в журнал); без подтверждённой почты — только баннер, вход разрешён.
2. Роль `admin` и минимальный API админки контента: CRUD профессий, блоков, тем, навыков, синонимов, материалов; смена статуса материала. Доступ только `admin`. Первый админ — командой `api create-admin`.
3. Онбординг и оценка навыков: выбор профессии, самооценка по ключевым навыкам (0 / 0,5 / 1), проверочный вопрос для «уверенно» (`check_questions`, `assessments`, `assessment_answers`, `user_skill_levels`). Уровень навыка общий для всех профессий.
4. % соответствия и краткий отчёт о разрыве считаются из оценки + «Изучено» (берём максимум уровня). Отчёт не хранится.
5. План «что учить дальше» резервным алгоритмом (без ИИ): `plans`, `plan_versions`, `plan_items`; каждая пересборка — новая версия.
6. Сервис аналитики: расписание (APScheduler в контейнере), журнал загрузок, `unknown_terms` (частые неизвестные слова из вакансий) для ручного разбора Рустамом; удаление сырых вакансий старше 12 месяцев.
7. «Работа России» — второй источник, склейка дублей (`dedup_hash` / `duplicate_of_id`).
8. Лист ожидания (`waitlist`) — `POST /api/v1/waitlist` для лендинга.
9. Тесты: Go — на auth, match и план; Python — на поиск навыков по синонимам. CI не обязателен, но `go test ./...` и `pytest` должны проходить.
10. **Передача фронтенда Жене** — см. ниже.
