# Карьерный навигатор IT

Веб-платформа для начинающих IT-специалистов. Она показывает, каких навыков человеку не хватает до требований реальных вакансий в России, и строит персональный план, как их закрыть. Проект делает студенческая команда УУНиТ в акселераторе GameLab (сентябрь — середина декабря 2026).

Перед любой крупной задачей сверяйся с `docs/product/structure.md` (полная структура платформы) и `docs/db/schema.dbml` (схема БД). Если требование там не описано — не придумывай, спроси.

## Продукт в одном абзаце

Аудитория — junior без первой работы в IT (выпускники вузов, колледжей, курсов); позже студенты, свитчеры, вузы (B2B). Путь пользователя: профориентация (если профессия не выбрана) → оценка навыков → отчёт о разрыве с вакансиями → персональный план со сроками → отметки «Изучено». Модель — freemium: каталог, roadmap, профориентация и оценка бесплатно; полный отчёт и персональный ИИ-план — подписка 250 ₽/мес. Платформа не обучает сама: она подбирает проверенные командой материалы (курсы, видео, статьи) и проекты.

## Стек и архитектура

**Сервисы.** Платформа — три сервиса, у каждого своя папка, свой контейнер и свой владелец:

| Сервис | Папка | Владелец | Связь с остальными |
|---|---|---|---|
| backend (Go): `api` + `worker` | `backend/` | Юрий | Отдаёт HTTP API фронтенду по `api/openapi.yaml`; читает результаты аналитики из БД |
| аналитика (Python) — `collector` | `collector/` | Юрий | Только через PostgreSQL (см. «Граница Go ↔ Python»), HTTP не отдаёт |
| frontend (React SPA) | `frontend/` | Евгений | Только HTTP к backend; стандарты — `docs/frontend-handoff.md` |

Сервисы не вызывают друг друга напрямую, кроме frontend → backend по HTTP. Каждый сервис пишет только в свои таблицы. В папку `frontend/` без просьбы Юрия не пиши — это зона Жени.

- **Бэкенд:** Go + gin. Сервис `api` (внутри — модули по доменам: auth, content, progress, match, plan, admin) + отдельный `worker` для фоновых задач (запросы к языковой модели, письма).
- **Аккаунт (решение 05.11):** пароли — argon2id; сессия — непрозрачный токен в httpOnly-cookie, в БД только хеш (`sessions.refresh_token_hash`), 30 дней; JWT не используем. Формат ошибки API: `{"error": {"code": "...", "message": "..."}}`, префикс путей `/api/v1`.
- **Сбор и анализ вакансий:** отдельный модуль `collector/` на Python 3.12 (решение 22.10). Сбор: httpx (SuperJob, «Работа России»), Telethon (Telegram-каналы); БД — psycopg 3; запуск по расписанию — cron или APScheduler в отдельном Docker-контейнере. pandas и pymorphy3 — только когда понадобятся. С Go-бэкендом общается только через общую базу.
- **БД:** PostgreSQL 16. Миграции — **goose** (решение 05.11): SQL-файлы в `backend/migrations`, накатываются при старте api или командой `api migrate`.
- **Контракт API:** OpenAPI — источник истины. Фронтенд генерирует типы из спецификации и может работать на моках до готовности бэкенда.
- **Фронтенд:** React + TypeScript + Vite, SPA.
- **Хостинг:** только российский (152-ФЗ, ч. 5 ст. 18 — ПД граждан РФ хранятся в РФ). Провайдер ещё не выбран.
- **Оплата:** СБП через российский платёжный сервис (не выбран). Пока нет юрлица/ИП — подписка на пилоте выдаётся промокодами.
- **Почта:** сервис не выбран; на этапе 1 письма пишем в лог.
- **Бэкенд, детали (21.10):** модуль `careernav` в `backend/`; драйвер БД — pgx v5 (`pgxpool`); журнал — стандартный `log/slog` (текст локально, JSON на серверах); конфиг — переменные окружения (`internal/config`), шаблон — `.env.example`, сам `.env` не коммитим.
- **Репозитории (решение 06.11):** рабочий — `github.com/Diablo1322/IT-career-navigator` (этот, `Code/`): здесь ведём backend и аналитику; фронтенда здесь нет, функционал проверяем демо-страницей `/demo/`. Общий — `github.com/kayeros/IT-career-navigator` (весь проект, там же фронтенд Жени и его прототип `index.html` на GitHub Pages). Клон общего — рядом с рабочим, в `Карьерный_IT_навигатор/full_code` (то есть `../full_code` от `Code/`). Выгрузка: `python scripts/sync_full_code.py` (предпросмотр) → `--apply` → коммит и push в `../full_code`. Скрипт меняет только наши пути (`backend/`, `collector/`, `api/`, `docs/`, `scripts/`, `docker-compose.yml`, `.env.example`, `.gitignore`, `.gitattributes`, `CLAUDE.md`); файлы Жени не трогает и не удаляет. Правки в общем репозитории в наших путях не делаем — только через рабочий и выгрузку.
- **Локальный запуск:** `cp .env.example .env`, затем `docker compose up --build` (PostgreSQL 16, api на :8080, worker). Проверка: `GET /health` → 200, если база доступна, иначе 503. Тесты: `cd backend && go test ./...`.
- **Срез 0 (05.11):** миграции накатываются при старте api; контент — `docker compose exec api /app/api seed` (YAML в `backend/migrations/seed/`, библиотека `gopkg.in/yaml.v3`). Сервис `collector` — в профиле `tools`: `docker compose run --rm collector load-superjob --profession qa-manual`, затем `match-skills`, `calc-weights`; тесты — `docker compose run --rm --entrypoint pytest collector`. Демо-страница — `http://localhost:8080/demo/` (только `APP_ENV=local`). В Git Bash перед `docker compose exec ... /app/...` нужен `MSYS_NO_PATHCONV=1`.

Предлагаемая структура репозитория (не утверждена, можно менять):

```
backend/   Go: cmd/api, cmd/worker, internal/<модуль>, migrations/
collector/ Python: сбор вакансий, дубли, поиск навыков, веса
frontend/  src/...
api/       openapi.yaml
docs/      документация (см. ниже)
```

## Граница Go ↔ Python (`collector`)

- Общаются только через PostgreSQL, прямых вызовов между сервисами нет.
- **`collector` пишет:** `vacancy_sources` (служебные поля), `import_runs`, `vacancies`, `vacancy_skills`, `unknown_terms`, `weight_snapshots`, `skill_weights`; также чистит сырые вакансии старше 12 месяцев.
- **`collector` только читает:** `professions`, `skills`, `skill_synonyms`, `profession_skills` — справочник правится через админку на Go.
- **Go-бэкенд пишет всё остальное** и только читает опубликованные веса (`weight_snapshots.status = published`) для % соответствия и планов.
- **Миграции — только в `backend/migrations`.** `collector` работает с готовой схемой и своих миграций не заводит.
- Запросы к языковой модели и письма — только в Go-воркере.

## Языковые модели — важно

- Только отечественные модели, данные не покидают Россию. Основная — **YandexGPT 5.1 Pro** (Yandex AI Studio), запасная — **GigaChat 2 Pro**. Зарубежные модели (включая Claude, OpenAI, DeepSeek) в продукте не используем.
- Модель подключается через заменяемый слой (интерфейс провайдера), чтобы переключаться без переписывания логики.
- **Разбор вакансий (в `collector`) — без языковой модели:** навыки выделяются по справочнику навыков и синонимам (`skills`, `skill_synonyms`). Частые неизвестные термины копятся в `unknown_terms` для ручного разбора.
- **План строит модель** по алгоритму, заданному в промпте; результат проверяется по справочнику. Если модель недоступна — план строит резервный алгоритм без ИИ.
- Каждый запрос к модели пишется в `ai_requests` (модель, токены, стоимость) — для дневного лимита и расчёта цены. Ориентир себестоимости — ≈6 ₽ за план.
- Промпт и настройки ИИ в админке — позже, не на этапе 1.

## Ключевые бизнес-правила

- **Вакансии:** источники — SuperJob API, «Работа России», Telegram-каналы; hh.ru — только позже через партнёрский доступ (публичный API закрыт с апреля 2026), ручной выборки с hh нет. Уникальность — (источник, external_id); дубли между источниками склеиваются через `dedup_hash` / `duplicate_of_id`. Сырые вакансии храним 12 месяцев.
- **Веса навыков:** пересчёт раз в месяц по профессии (`weight_snapshots`, `skill_weights`); вес = доля вакансий профессии с этим навыком; минимум 200 вакансий для расчёта; вес < 0,05 — навык необязательный.
- **% соответствия:** Σ(вес × уровень) / Σ весов по ключевым навыкам профессии. Уровень навыка 0 / 0,5 / 1; «уверенно» засчитывается после проверочного вопроса. Процент пользователь видит.
- **Уровень навыка общий для всех профессий** (`user_skill_levels`): Git, изученный в одной профессии, засчитывается везде.
- **Темы — общая библиотека** (`topics`): тема хранится один раз и ставится в блоки разных профессий через `block_topics`.
- **Профориентация:** баллы вариантов ответов скрыты от пользователя, он видит топ-3 профессии с % и причинами.
- **Отчёт о разрыве не хранится** — считается из оценки и снимка весов.
- **Планы:** без лимита по числу профессий; каждая пересборка — новая версия (`plan_versions`, `plan_items`).
- **Материалы:** пользователь видит только одобренные (`approved`). Материалы, предложенные ИИ, сначала `ai_suggested`, команда проверяет вручную. Новые навыки из вакансий проходят статусы new → in_review → verified.
- **Подписка:** состояния — ожидает оплаты / активна / не удалось списать / отменена / заморожена; автопродление с возможностью отмены. При окончании подписки персональный план замораживается.
- **Почта подтверждается** обязательно (без неё нельзя оплатить).
- **Удаление аккаунта** — полное; платежи остаются обезличенными (`user_id` обнуляется).
- **Согласия** (ПД, рассылки) — журнал с версией документа и датой отзыва (`consents`).

## Требования к качеству

- HTTPS, пароли только хешем (argon2id или bcrypt), защита от перебора, роли доступа (user / admin), ежедневные бэкапы БД.
- Страница — быстрее 2 с; построение плана — до 30 с с индикатором.
- Браузеры: последние Chrome, Яндекс Браузер, Firefox, Edge, Safari, Opera. Адаптив под телефон — к этапу 3.
- Журнал ошибок, оповещение о падении.
- Код — в репозитории с историей (нужно для регистрации программы для ЭВМ в Роспатенте), документация по модулям.

## Как работать в этом репозитории

- Идентификаторы в коде — на английском; комментарии, документация и сообщения коммитов — на русском.
- Не добавляй зависимости и сервисы, не согласованные выше, без вопроса (особенно зарубежные облака и API).
- Меняешь контракт — сначала `api/openapi.yaml`, потом код.
- Меняешь схему БД — сначала `docs/db/schema.dbml`, потом миграция.
- Когда принимается новое решение (стек, хостинг, правило), допиши его в этот файл.
